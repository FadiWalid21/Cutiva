# قوالب المنتجات — شرح المدخلات والـ Backend والفرق عن الإعدادات

**آخر تحديث:** 18 أكتوبر 2026  
**الشاشة:** `/product-templates` (خلف الـ feature flag `ProductTemplates`)  
**الـ API:** `/api/product-templates/...`

---

## 1. ما هي صفحة قوالب المنتجات؟

القالب = **وصفة إنتاج**، مش مشروع عميل.

تقول للنظام **قبل** ما تدخل عرض وارتفاع عميل:

- الشباك/الباب من أي **قطع ألومنيوم** يتكون (حلق، ضلفة، شنكل…)
- **معادلة طول** كل قطعة من العرض والارتفاع
- أين **الزجاج** وبأي معاملات مقاس
- أي **إكسسوارات** وبأي قاعدة كمية

لما تضيف عنصر في المشروع وتضغط «احسب»، النظام يطبّق الوصفة دي على الأبعاد الفعلية.

### البذرة الأولى (Seed)

أول ما الـ API يشتغل وما فيش قوالب في الـ DB، `ProductTemplateSeeder` يضيف:

| النوع | التنويعات |
|---|---|
| شباك (Window) | سحاب (Sliding)، مفصلي (Casement)، قلاب (Tilt) |
| باب (Door) | ألومنيوم فقط، ألومنيوم + زجاج |

الأرقام الأولية **تجريبية** (`IsSeeded = true`) — مفروض الورشة تعدّلها من الشاشة قبل الاعتماد عليها.

## 2. المدخلات من المستخدم بالتفصيل

الصفحة **ما بتنشئش** أنواع جديدة من الصفر في الـ MVP؛ بتعرض الكتالوج الموجود وتعدّل التنويع والأجزاء.

### أ) رأس التنويع (Variant)

| المدخل | المعنى | يروح فين؟ |
|---|---|---|
| الاسم | الاسم اللي يظهر في قائمة المشروع | `ProductVariant.Name` |
| عدد الضلف (SashCount) | مثلاً 2 للسحاب؛ يدخل في تقسيم العرض | `ProductVariant.SashCount` |
| التداخل مم (OverlapMm) | تراكب الضلف؛ يدخل مع التقسيم | `ProductVariant.OverlapMm` |
| نشط | لو مقفول، التنويع يختفي من قوائم المشروع | `ProductVariant.IsActive` |

**API:** `PUT /api/product-templates/variants/{id}`

---

### ب) معادلات القطع (TemplatePart) — لكل دور

كل صف = دور ألومنيوم واحد (مثل `FrameTop`, `FrameBottom`, `FrameJamb`, `SashStile`, `SashRail`, `InterlockStile`).

| المدخل | المعنى |
|---|---|
| الدور (Role) | ثابت من القالب (للعرض فقط في الـ UI) |
| الاسم المعروض | تسمية القطعة في الواجهة والتقارير |
| الكمية لكل وحدة | كم قطعة من هذا الدور **لكل منتج واحد** (مثال: قائمان → 2) |
| معامل العرض (WidthCoef) | كم من عرض الفتحة يدخل في الطول |
| معامل الارتفاع (HeightCoef) | كم من ارتفاع الفتحة يدخل في الطول |
| الإزاحة مم (OffsetMm) | خصم/إضافة ثابتة (ممكن سالب؛ لو الناتج ≤ 0 الحساب يرفض) |
| تقسيم عرض الضلفة | لو مفعّل: العرض المستخدم = `(W ÷ SashCount) + OverlapMm` بدل `W` كامل |
| ألومنيوم افتراضي | مادة افتراضية لما تضيف عنصر مشروع (المستخدم يقدر يغيّرها هناك) |

**المعادلة (بدون تنفيذ نصوص):**

```text
الطول (مم) = تقريب(
  معامل_العرض × العرض_الفعّال
  + معامل_الارتفاع × الارتفاع
  + الإزاحة
)

العرض_الفعّال =
  لو تقسيم الضلفة مفعّل: (العرض ÷ عدد_الضلف) + التداخل
  وإلا: العرض
```

**مثال توضيحي (أرقام شكل فقط):** ضلع جانبي بارتفاع كامل وخصم حلق  
`HeightCoef = 1`, `WidthCoef = 0`, `OffsetMm = -40` → الطول ≈ ارتفاع الفتحة − 40 مم.

**API:** `PUT /api/product-templates/parts/{id}`

---

### ج) فتحات الزجاج (TemplateGlassSlot)

| المدخل | المعنى |
|---|---|
| الاسم | مثل «لوح الضلفة» |
| عدد الألواح (PaneCount) | كمية الألواح لكل منتج (ثم تتضاعف بكمية العنصر في المشروع) |
| معاملات عرض الزجاج | `GlassW` من عرض/ارتفاع الفتحة + إزاحة |
| معاملات ارتفاع الزجاج | `GlassH` بنفس الأسلوب |
| مطلوب؟ | لو نعم، لازم اختيار زجاج في المشروع |
| تقسيم عرض الضلفة | نفس فكرة السحاب على مقاس اللوح |

**المساحة لاحقاً في الحساب:**  
`Area(m²) = GlassW(مم) × GlassH(مم) / 1_000_000` (بدون تقريب في الـ MVP).

**API:** `PUT /api/product-templates/glass-slots/{id}`

الباب «ألومنيوم فقط» مفيهوش فتحات زجاج؛ «ألومنيوم + زجاج» فيه.

---

### د) فتحات الإكسسوار (TemplateAccessorySlot)

| المدخل | المعنى |
|---|---|
| الاسم | قفل، عجلة، مقبض… |
| قاعدة الكمية | `PerProduct` = لكل منتج · `PerSash` = لكل ضلفة × SashCount |
| الكمية (Qty) | مضاعف القاعدة |
| إكسسوار افتراضي | من كتالوج الورشة (صفحة الموارد) |

**API:** `PUT /api/product-templates/accessory-slots/{id}`

---

### ما لا يُدخل في صفحة القوالب

- عرض × ارتفاع العميل  
- كمية الطلب في المشروع  
- أسعار يوم الحساب (بتتاخد من الموارد وقت «احسب»)  
- اختيار المادة لكل دور لطلب معيّن (ده في صفحة المشروع)

## 3. ماذا يفعل الـ Backend؟

```text
ProductTemplateSeeder ──► كتالوج القوالب (ProductType / Variant / Parts / Glass / Accessory slots)
         ▲
         │ PUT من صفحة القوالب (تعديل فقط)
         │
ProjectItem (أبعاد + اختيارات) ──► ProjectCostCalculator
         │                              │
         │                              ├─► أطوال ألومنيوم → ICuttingPlanOptimizer (موجود)
         │                              ├─► زجاج (م² × سعر)
         │                              ├─► إكسسوارات (كمية × سعر)
         │                              └─► RequiredCuts بمصدر العنصر + Snapshot على العنصر
```

### عند فتح/حفظ القالب فقط

| العملية | السلوك |
|---|---|
| `GET /api/product-templates/types` | قائمة الأنواع والتنويعات — **بدون** حساب تكلفة |
| `GET /api/product-templates/variants/{id}` | تفاصيل التنويع + الأجزاء والفتحات |
| `PUT` على variant / part / glass / accessory | يحدّث صفوف الـ DB فقط |

تعديل القالب **ما بيغيّرش** تلقائياً مشاريع اتحسبت قبل كده. كل عنصر مشروع يخزّن `CalculationSnapshotJson` عند آخر حساب ناجح.

### عند «احسب» في المشروع (`POST /api/projects/{id}/calculate`)

1. يقرأ عناصر المشروع + القالب + المواد/الزجاج/الإكسسوارات المختارة  
2. يفك BOM عبر `ProjectCostCalculator` (خدمة pure بدون DB داخلها)  
3. يجمع قطع الألومنيوم حسب المادة ويعذّي الـ optimizer الحالي (FFD + kerf + remnants) — **من غير ما يغيّر منطق الـ optimizer**  
4. يحسب الزجاج والإكسسوارات  
5. يوزّع تكلفة العيدان المشتركة على العناصر بنسبة طول القطع (+ نصيب من الهدر)  
6. يمسح فقط `RequiredCut` اللي ليها `SourceProjectItemId` ويعيد توليدها  
7. يخزّن لقطة الحساب على كل عنصر (للـ quote لاحقاً)

الملف المرجعي للمعادلات:  
`src/CuttingOptimizer.Application/Services/Costing/ProjectCostCalculator.cs`

## 4. الفرق: قوالب المنتجات × الإعدادات × الموارد

| | قوالب المنتجات | الإعدادات | الموارد |
|---|---|---|---|
| **السؤال اللي بتجاوب عليه** | المنتج بيتركّب إزاي؟ | كام سعر إنتاج المتر؟ وإيه أنواع العناصر القديمة؟ | بنشتري إيه وبكام؟ |
| **المحتوى** | أنواع شباك/باب، تنويعات، معادلات قطع، فتحات زجاج/إكسسوار | سعر إنتاج م² للورشة؛ قطاعات (Sector) وربطها بمادة افتراضية | ألومنيوم + أطوال/أسعار؛ أنواع زجاج + سعر م²؛ إكسسوارات |
| **النطاق** | كتالوج قوالب مشترك (عام) | سعر الإنتاج = ورشة؛ Sector = عام | ألومنيوم عام؛ زجاج وإكسسوار = لكل ورشة |
| **دورها في V2** | أساس عناصر المنتج والحساب | Sector للـ flow اليدوي القديم لو الـ flag مقفول؛ **مش** بديل عن القالب | القالب بيشير لمواد/إكسسوارات من هنا كقيم افتراضية |

**جملة واحدة للمستعمل:**

> **الموارد** = ماذا تشتري وبكم.  
> **القوالب** = كيف يتركّب الشباك/الباب.  
> **الإعدادات** = تسعير العمالة (م²) وإعداد أنواع العناصر القديمة.

ملاحظة: بعد تفعيل موارد V2، قائمة «موارد السوق» اتشالت من الـ sidebar لصالح «الموارد». رابط الإعدادات لصفحة المواد القديمة يحوّل لـ `/resources` لما الـ flag شغال.

## 5. مسار عملي مختصر

1. **الموارد:** أضف أنواع ألومنيوم + أطوال الشراء والأسعار، أنواع الزجاج وأسعار المتر، الإكسسوارات.  
2. **قوالب المنتجات:** افتح تنويع (مثل سحاب) وعدّل المعاملات والإزاحات لأرقام الورشة الحقيقية؛ راجع الزجاج والإكسسوارات الافتراضية.  
3. **مشروع:** أضف عنصر (نوع → تنويع → عرض×ارتفاع×كمية → اختيارات مواد/زجاج) → **احسب** → راجع قائمة الشراء والتكلفة → عرض السعر.
